1996

FTP는 인터넷의 공용어였다

그리고 CuteFTP는 그 시대에 가장 손에 익는 도구였습니다. 왼쪽엔 내 컴퓨터, 오른쪽엔 원격 서버, 가운데로 끌어다 놓으면 파일이 넘어갔죠. 매뉴얼도, 명령어 옵션도 없이 한눈에 쓸 수 있었습니다. 많은 이들의 첫 웹사이트, 첫 백업, 클라이언트에게 처음 보낸 파일이 그 듀얼 페인 창에서 떠났습니다.

2006

규칙이 다시 쓰였다

2006년 3월 14일, AWS가 S3를 발표했습니다. 20년이 지난 지금, S3는 더 이상 하나의 서비스가 아니라 클라우드 스토리지의 사실상 표준입니다. Cloudflare R2, Google Cloud Storage의 XML API, Backblaze B2, MinIO — 오늘날 이름을 댈 수 있는 오브젝트 스토리지는 거의 모두 같은 언어를 말합니다.

듀얼 페인, 드래그 앤 드롭

왼쪽은 소스, 오른쪽은 대상. 파일, 폴더, 트리 전체 — 끌어다 놓으면 전송이 시작됩니다. 인터페이스 자체가 매뉴얼입니다.

S3를 말하는 곳이라면 어디든

Amazon S3, Cloudflare R2, Backblaze B2, MinIO, 그리고 모든 S3 호환 엔드포인트. 모든 쪽이 양방향 — 로컬↔클라우드, 클라우드↔클라우드 모두 됩니다.

샌드박스 안에서 실행

RocketBucket은 Apple App Sandbox 안에서 최소 권한으로 실행됩니다. 당신이 건네준 폴더만 다루고, Mac의 다른 어떤 것에도 손대지 않습니다.

키는 Keychain에

시크릿 키는 macOS Keychain에 저장되며, 디스크의 설정 파일에는 절대 기록되지 않습니다. IAM Identity Center(AWS SSO) 로그인도, 액세스 키 붙여넣기도 지원합니다.

병렬 멀티파트 전송

큰 파일은 병렬 멀티파트 스트림으로, 수천 개의 작은 파일은 여러 커넥션에 분산해서. 어느 쪽이든 드래그 한 번이면 끝납니다.

SDK 없음, 군더더기 없음

S3 서명은 URLSession 위에 직접 구현한 SigV4로, 실제 AWS S3와 MinIO를 상대로 검증했습니다. 의존성 제로 — 몰래 어디로도 보고하지 않습니다.

자주 묻는 질문

어떤 서비스를 지원하나요?

Amazon S3, Cloudflare R2, Backblaze B2, MinIO, 그리고 S3 API를 구현한 모든 엔드포인트. 로컬 폴더도 일급 엔드포인트라서 로컬↔클라우드, 클라우드↔클라우드 조합 모두 같은 방식으로 동작합니다.

내 데이터가 당신들의 서버를 거치나요?

아니요. 전송은 당신의 Mac에서 스토리지 엔드포인트로 TLS를 통해 직접 이루어집니다. 중계 서버도, 계정 가입도, 분석 추적도 없습니다.

자격 증명은 어디에 저장되나요?

시크릿 액세스 키는 macOS Keychain에 저장되며, 디스크의 설정 파일에는 기록되지 않습니다. IAM Identity Center(AWS SSO)로 로그인하면 장기 키를 전혀 남기지 않고 단기 자격 증명만으로 쓸 수도 있습니다.

정말 CuteFTP처럼 쓸 수 있나요?

레이아웃은 같습니다: 두 개의 페인, 왼쪽은 소스, 오른쪽은 대상, 가운데로 드래그. 바뀐 건 속입니다 — FTP 대신 SigV4 서명된 S3 요청과 병렬 멀티파트 전송 — 그리고 보안 모델: 샌드박스 실행, 키는 Keychain에.
