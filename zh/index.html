三十年前，我們就知道這件事該怎麼做

一段關於傳檔案的簡短歷史——以及我們為什麼做了 RocketBucket。

1996

FTP 是網路的通用語言

而 CuteFTP 是那個年代最順手的工具——左邊是你的電腦，右邊是遠端，中間拖一下，檔案就過去了。沒有教學文件，沒有指令參數，看一眼就會用。很多人的第一個網站、第一次備份、第一份交給客戶的檔案，都是從那個雙欄視窗送出去的。

2006

規則被改寫了

2006 年 3 月 14 日，AWS 發布 S3。二十年過去，它不再只是一個服務，而是雲端儲存的事實標準。Cloudflare R2、Google Cloud Storage 的 XML API、Backblaze B2、MinIO——今天你叫得出名字的物件儲存，幾乎都說同一種話。

今天

協議換了，但工具沒有跟上

我們現在有 CLI、有 SDK、有一堆要先讀三頁文件才能上傳一個檔案的主控台。快，但不再讓人一眼就會。

所以我們做了 RocketBucket。
拖進去就是上傳，拉出來就是下載。
你三十年前養成的操作習慣，在這裡一個都不用改。

安全與速度，就這兩件事

其他的一切，都是從這兩點長出來的。

雙欄拖放

左邊是來源，右邊是目的地。檔案、資料夾、整棵目錄樹——拖過去就開始傳。介面本身就是說明書。

說 S3 的地方都能去

Amazon S3、Cloudflare R2、Backblaze B2、MinIO，以及任何相容 S3 的端點。每一端都是雙向的——本機↔雲端、雲端↔雲端都行。

在 Apple 沙盒裡運行

RocketBucket 跑在 Apple 沙盒裡，權限最小化。它只碰你交給它的資料夾，你 Mac 上的其他東西一概碰不到。

金鑰存在 Keychain

Secret key 存在 macOS Keychain，絕不以明文寫進磁碟上的設定檔。支援 IAM Identity Center（AWS SSO）登入，也可以直接貼上 access key。

多執行緒平行傳輸

大檔用平行 multipart 分段上傳；幾千個小檔分散到多條連線。一次拖放，兩種情況都搞定。

沒有 SDK、沒有累贅

S3 簽名是手寫的 SigV4 實作，跑在 URLSession 上，對真實的 AWS S3 與 MinIO 驗證過。零依賴——不會偷偷回報任何東西。

常見問題

RocketBucket 支援哪些服務？

Amazon S3、Cloudflare R2、Backblaze B2、MinIO，以及任何實作 S3 API 的端點。本機資料夾也是一級端點，所以本機↔雲端、雲端↔雲端的組合，用法完全一樣。

我的資料會經過你們的伺服器嗎？

不會。傳輸從你的 Mac 直接走 TLS 到你的儲存端點。沒有中繼、不用註冊帳號、沒有任何分析追蹤。

我的憑證存在哪裡？

Secret access key 存在 macOS Keychain，絕不寫進磁碟上的設定檔。你也可以透過 IAM Identity Center（AWS SSO）登入，取得短效憑證，完全不留長期金鑰。

真的跟 CuteFTP 一樣好用嗎？

版面是一樣的：兩個窗格，左邊是來源，右邊是目的地，中間拖一下。變的是底層——SigV4 簽名的 S3 請求加上平行 multipart 傳輸，取代了 FTP——還有安全模型：沙盒運行、金鑰存在 Keychain。
