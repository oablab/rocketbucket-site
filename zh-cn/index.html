1996

FTP 是网络的通用语言

而 CuteFTP 是那个年代最顺手的工具——左边是你的电脑，右边是远端，中间拖一下，文件就过去了。没有教程文档，没有命令参数，看一眼就会用。很多人的第一个网站、第一次备份、第一份交给客户的文件，都是从那个双栏窗口送出去的。

规则被改写了

2006 年 3 月 14 日，AWS 发布 S3。二十年过去，它不再只是一个服务，而是云端存储的事实标准。Cloudflare R2、Google Cloud Storage 的 XML API、Backblaze B2、MinIO——今天你叫得出名字的对象存储，几乎都说同一种话。

双栏拖放

左边是来源，右边是目的地。文件、文件夹、整棵目录树——拖过去就开始传。界面本身就是说明书。

说 S3 的地方都能去

Amazon S3、Cloudflare R2、Backblaze B2、MinIO，以及任何兼容 S3 的端点。每一端都是双向的——本机↔云端、云端↔云端都行。

在 Apple 沙盒里运行

RocketBucket 跑在 Apple 沙盒里，权限最小化。它只碰你交给它的文件夹，你 Mac 上的其他东西一概碰不到。

密钥存在 Keychain

Secret key 存在 macOS Keychain，绝不以明文写进磁盘上的配置文件。支持 IAM Identity Center（AWS SSO）登录，也可以直接粘贴 access key。

多线程并行传输

大文件用并行 multipart 分片上传；几千个小文件分散到多条连接。一次拖放，两种情况都搞定。

没有 SDK、没有累赘

S3 签名是手写的 SigV4 实现，跑在 URLSession 上，对真实的 AWS S3 与 MinIO 验证过。零依赖——不会偷偷回传任何东西。

常见问题

RocketBucket 支持哪些服务？

Amazon S3、Cloudflare R2、Backblaze B2、MinIO，以及任何实现 S3 API 的端点。本机文件夹也是一级端点，所以本机↔云端、云端↔云端的组合，用法完全一样。

我的数据会经过你们的服务器吗？

不会。传输从你的 Mac 直接走 TLS 到你的存储端点。没有中转、不用注册账号、没有任何分析追踪。

我的凭证存在哪里？

Secret access key 存在 macOS Keychain，绝不写进磁盘上的配置文件。你也可以通过 IAM Identity Center（AWS SSO）登录，取得短期凭证，完全不留长期密钥。

真的跟 CuteFTP 一样好用吗？

布局是一样的：两个窗格，左边是来源，右边是目的地，中间拖一下。变的是底层——SigV4 签名的 S3 请求加上并行 multipart 传输，取代了 FTP——还有安全模型：沙盒运行、密钥存在 Keychain。
